# Schedule response field 1 in both working hall captures

All nonempty `SelectVsSchedules`, `SelectCoopSchedules`, `SelectSeasonSchedules`, and `SelectVsParams` responses in both preserved working Nextendo hall captures have protobuf field 1 (`unk`) set to true. The corresponding generated SwitchNet response types have the same bool field, but the handlers previously left it at proto3's false default, so it was omitted from their wire responses. `SelectLeagueSchedules` in the working sessions does not carry this field, and remains unchanged.

SwitchNet now sets the flag for its populated Versus, Coop, Season, and VsParams answers. Empty Versus/Coop lists retain the old answer because the captures do not establish the flag's value for an empty list. A test marshals all four populated responses and checks the actual top-level wire field. The semantic name and whether this difference alone causes the hall error are unconfirmed; the change follows a repeatable captured response shape without importing Nextendo code or values.
