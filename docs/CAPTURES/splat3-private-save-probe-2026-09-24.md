## Hardware result (16:18 UTC)

The three raw protobuf messages were temporarily installed on the VM under `/var/tmp/switchnet-splat3-probe-20260924/`, mode 0600 and owned by `switchnet`, for the single account-scoped attempt authorized by the operator. The NPLN log confirms that CloudSave/GetSaveRecord served the 87-key substituted save at 16:18:25. The console visibly loaded that progression. It did not call GetDocument for either CoopUserAttribute or VsUserAttribute, so their substitutions were never exercised. At 16:18:59, the next document request was the same absent Hammer/UserAttribute/Data, answered `NotFound`; the hall still displayed the same communication error. This rules out an empty SaveRecord as a sufficient explanation for this attempt. It does not test whether the attribute documents themselves would be accepted if reached.

The temporary systemd override and all three VM protobuf copies were removed immediately after the attempt. NPLN restarted with its normal configuration and was listening again. Both original capture folders remain untouched. No captured payload was committed.

Nextendo's `ugcstore_absent.go` records earlier experiments with three missing-document shapes: an OK response with no message crashed the client's resource-name parser; a named empty Document avoided that crash but did not clear the hall communication error; the later two-frame `NotFound` with `NError` was retained. GRID0+ already sends that final shape for Hammer, consistent with the preserved working capture's status and trailers. The next comparison should therefore examine the request/response sequence immediately preceding the hall error, rather than revisiting the same absent-document hypothesis.
