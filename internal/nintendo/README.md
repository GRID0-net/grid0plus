# nintendo

The list of Nintendo hostnames GRID0+ replaces, and which service answers each. **This is the
single source of truth.** Three things have to agree exactly, and all three are generated from
this list:

| Output | Generated by | If it disagrees |
| --- | --- | --- |
| `switch/hosts.txt` | `switchnetctl hosts` | the console sends a request to real Nintendo, or nowhere |
| the nginx routing map | `switchnetctl nginx` | the console reaches the wrong service and gets an answer it can't parse |
| the certificate names | `scripts/gen-certs.sh`, via `switchnetctl sans` | the handshake fails with nothing in any log naming the missing hostname |

Adding a host in one place and forgetting another produces a failure with no useful error.
Adding it here fixes all three.

Reference: [Server List](https://github.com/kinnay/NintendoClients/wiki/Server-List).

## Ordering matters

Atmosphère's DNS-MITM applies the **last matching line**. `Hosts` is declared in the order it
should be written, so broad entries come first and specific overrides last. That is why the
`nncs2` line comes after `nncs1`.

In the hosts file, `*` matches zero or more characters and `%` expands to the environment
(`lp1`). Those are DNS-MITM patterns, not DNS names, so a wildcard can never go into a
certificate name or an nginx `server_name`. The `Wildcard` and `TLSNames` fields handle that.

## Not everything is redirected

Two service values mean "don't send this to GRID0+".

**`ServiceBlackhole`** hosts are null-routed to `0.0.0.0`. These are the telemetry hosts, the
store hosts (not part of GRID0+) and the `d4c` system-update hosts. There is nothing useful to
do with a console's crash and play reports, and answering them only fills the log. The
system-update hosts are null-routed because this deployment's console never goes back to real
Nintendo.

**`ServicePassthrough`** keeps a host resolving to real Nintendo. For a console that moves
back and forth between GRID0+ and Nintendo, the `d4c` system-update hosts must pass through,
because the `nim` system module stores a persistent flag when the update check fails and that
flag survives switching back. Nothing in `Hosts` uses this value today. If you reuse the list
for a console that moves between the two, change those hosts to it first. `hosts_test.go`
asserts their classification because getting it wrong can't be undone from the server.
