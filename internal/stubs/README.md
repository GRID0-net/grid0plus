# internal/stubs

A catch-all for the Nintendo endpoints SwitchNet redirects but does not
implement.

| | |
| --- | --- |
| Needs a database | no |
| Routing | by `Host` header — one process sits behind many hostnames |

## Why answer them at all

Many console services treat a *failed* request as a fault rather than as "that
feature is unavailable", and the failure lands somewhere unhelpful. The clearest
case is the connection test: a console that cannot reach it decides it is behind a
captive portal, and the user sees "this feature is not available" rather than a
network error.

Answering with a well-formed empty result is what keeps the console quiet about
things that are genuinely not part of this stack.

## What each host gets

| Host contains | Answer | Why that shape |
| --- | --- | --- |
| `ctest`, `conntest` | `ok`, plus `X-Organization: Nintendo` | the console checks both the body and the header; JSON here is a captive-portal signal |
| `.frs.` | `[]` | friend recommendations — there is nobody to recommend |
| `.five.` | `[]` | online play invitations — phase 2 |
| `.op2.` | `{"active": true, …}` | membership verification; every registered user may play |
| `service-status` | everything up | if it were not, the console learning it here would not help |
| `.dragons.` | `{}` | eLicense; `aauth` accepts the token without looking at it |
| anything else | `{}` | well-formed JSON beats a 404 for a client whose expectations are unknown |

Empty **lists**, not `null`: a console decoding `null` into a list type fails.

## The log is the to-do list

Every stubbed request is logged with its host, path and user agent. An endpoint
that turns up here repeatedly is one that may need implementing for real.

`stubs.log_bodies: true` also logs request bodies. Invaluable exactly once, while
working out what an unimplemented endpoint is being asked for; far too chatty to
leave on.

The nginx config generated by `switchnetctl nginx` routes **unmatched hostnames**
here through a `default_server` block, so a host that was redirected on the
console but has no server block shows up as a log line rather than getting an
answer from whichever service nginx happened to list first.

## The BCAT probe

`bcatprobe.go` is an **instrument, not a service**, and it is off by default.

SwitchNet cannot serve BCAT. The `list` response body is undocumented, and
whether the console verifies the delivery container's RSA-2048 signature has
never been established — switchbrew documents the *field* and says nothing about
a verification step. A console running SwitchNet already has sigpatches, so the
check may well be bypassed; nobody has looked.

The probe settles the cheap half of that. Turned on, it answers the three
`bcat-*` hosts, logs each request in full — method, path, query, every header,
a hexdump of the body — and replies `200` with an **empty body**. The empty body
is deliberate: anything else would be an invented protocol shape. What the
console does next is itself the finding.

Running it needs **both** halves, and neither does anything alone:

```sh
# 1. point the console's bcat-* hosts here instead of null-routing them
switchnetctl hosts -bcat-probe > /path/to/sd/atmosphere/hosts/sysmmc.txt   # and emummc.txt

# 2. turn the probe on
#    stubs.bcat_probe: true   (or SWITCHNET_STUBS_BCAT_PROBE=1)
```

Then open Splatoon 3 and watch the log. `cmd/stubs` prints a loud warning at
start-up when the probe is on, so a flag that did not take is obvious.

**Turn it back off afterwards.** Answering a console that expected content turns
an immediate, legible failure into a hang — which is exactly why those hosts are
null-routed the rest of the time. Write up whatever the console did under
`docs/CAPTURES/`; either answer is worth having. See `TODO.md` §2.4 for the
second stage, and §5.2 for why the null route is contingent rather than a rule.
